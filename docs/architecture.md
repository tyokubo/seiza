# 技術設計・ディレクトリ方針

## 目的

早く触れるプロトタイプを作りつつ、視点操作／描画／探索／保存の変更が互いに波及しにくい構成にする。大規模なClean Architectureの雛形は不要。

## 推奨スタック

- TypeScript / React Native / Expo / Expo Router
- 星と線の描画：まず必要性を検証し、React Native Skiaを優先候補とする（初期に不要なら導入を先送り）。
- センサー：expo-sensors（ジャイロ対応段階で導入）
- 振動：expo-haptics（実機検証段階で導入）
- 保存：MVPはローカル、クラウド同期が必要になったらSupabase
- テスト：純粋関数の単体テストを優先。テストランナーは採用時に選定する。

## 依存の向き

- `domain/` はTypeScriptのみ。React・描画ライブラリ・Supabaseをimportしない。
- 描画コンポーネントは、カメラ状態と星データから描画する。保存処理を直接呼ばない。
- 背景描画はゲームロジックから分離し、後から画像・Skia・ネイティブ描画へ差し替えられるようにする。背景画像には発見対象の星や星座を含めず、星は座標データから動的に描画する。
- 2:1のEquirectangular全天球画像は、`expo-gl` のGLViewで球面方向にサンプリングする。`ImageBackground`のcover/containや通常の2D拡大縮小では使用しない。
- 入力層はスワイプやセンサー値をカメラ操作へ変換する。ドメインが入力デバイスを知らないようにする。
- 画面・hookはドメイン・描画・保存を組み合わせる。
- 保存APIはRepositoryを窓口にする。Supabaseを全画面から直接呼ばない。
- ドメイン間の共通化は実際に必要になってから行う。

## カメラ仕様の重要な区別

- カメラには視点位置/方向と表示モードがある。
- `normal`と`telescope`は**入力感度と視野サイズ**が違う。
- `telescope`の可動範囲そのものは制限しない。
- 望遠鏡へ入るときは視点を維持し、通常へ戻るときは利用できる入力方式に応じて向きを復元する。
- カメラ姿勢は単位クォータニオンで保持し、描画ピクセルと独立して更新する。

  telescopeSwipeSensitivity: 0.2,

## データフロー

```text
スワイプ/端末姿勢
  -> 操作変換
  -> カメラ状態の更新
  -> 視野・探索円内の未発見星密度・対象星・距離/方向の計算
  -> 通常モードの背景濃淡 / 望遠鏡モードの星空・ダウジング表示
  -> 発見イベント
  -> セーブ処理（導入段階で）
```

`camera.ts`、`input.ts`、`skyDensity.ts`、`dowsing.ts`、`discovery.ts`はReact外でテスト可能にする。

入力はスワイプと端末姿勢を直接カメラに結びつけず、入力変換層を通す。`expo-sensors` DeviceMotionの alpha/beta/gamma 全軸から姿勢クォータニオンを構成する。基準端末姿勢をD0、基準カメラ姿勢をC0、現在の端末姿勢をDとし、ジャイロの目標姿勢は毎回 `C0 * inverse(D0) * D` から求める。連続サンプルの差分を切り捨てて積算しない。端末は縦持ちを前提とし、中心軸まわりの回転を含む姿勢を保持する。利用不可・未許可の場合や操作中の補助入力として、スワイプ操作だけでも成立させる。

震え防止にはクォータニオンの平滑化と1更新あたりの表示回転量上限を使う。上限を適用した姿勢を次の表示更新の起点とし、追従しきれなかった角度を失わず、停止後も現在の端末姿勢へ収束させる。微小回転の切り捨ては行わない。計算は `deviceMotion.ts`、スワイプ・モード・再調整との合成はReact非依存の `explorationState.ts` に置く。

スワイプ分は世界座標の独立した回転Sとして保持し、通常モードの表示は `S * 平滑化したジャイロ姿勢` とする。ドラッグ中も端末姿勢の追跡を継続する。望遠鏡モードでは端末姿勢のみ追跡して表示は固定し、望遠鏡のスワイプでは通常モードのSを変更しない。戻る際は最新の端末姿勢とSから通常の向きを復元する。端末姿勢がない環境では望遠鏡の表示方向を保つ。モード変更でD0/C0を取り直さない。ジャイロ再調整時は約420msの補間でSだけを単位回転へ戻し、その間も端末の最新姿勢を反映する。再調整中に新しいスワイプやモード変更を行った場合は再調整を中断する。

通常モードの探索円と望遠鏡モードの視野判定は、同じカメラ座標を基準にする。見た目の円サイズと星のタップ判定は画面に合わせ、投影関数を共有する。タップ対象は円形視野内の未登録星に限る。焦点移動と登録の状態遷移は `explorationState.ts` に置き、視野に入っただけでは登録しない。登録済みIDは通常モードの星描画にも渡し、`ConstellationProvider` とRepositoryを通じて端末に保存・復元する。

全天球の空と透過付き山レイヤーは、同じカメラ姿勢・視野角で球面方向をサンプリングする。描画順は空、星、山とし、山が星より手前に見えるようにする。各画像の正面・水平・ロールは素材固有であり、共通のカメラ投影だけでは空画像、山画像、星データ間の絶対的な位置合わせを保証しない。山の素材姿勢は `gameConfig.panorama.mountainRotationDegrees`（素材から世界へX→Y→Zの順に回転）で指定する。`sky/domain/panorama.ts` が逆回転を定義し、描画は「世界から素材への回転 × カメラ姿勢」、DBGは同じ回転で世界方向をUVへ変換する。現素材はX軸+90度で地面中心を世界の-Yへ配置する。黒半球による補完は行わず、地面の遮蔽には山画像のアルファを使う。背景に含まれる極小の星とゲーム内の星座データは別物で、実天球上の登録情報がない限り一致させない。探索対象星は球面方向のY成分が0以上の上半球に限定し、表示・密度・発見・ダウジングの対象を一致させる。星、密度判定、発見判定、ダウジングも同じカメラ姿勢と球面方向データを使う。星の2D生成座標はステレオ投影で球面方向へ変換し、カメラ姿勢から画面への透視投影で描画する。

円形視野の見た目はキャンバスサイズからピクセルで算出し、通常モードの探索円、望遠鏡モードの覗き窓、星の画面投影中心を同じ値に揃える。

## 永続化と更新

### 姿勢基準と星の表示の補足

- DeviceMotionのZ-up座標をX軸-90度で世界のY-upへ変換し、背面カメラの視線を端末の-Zとして扱う。開始時に揃えるのは方位だけで、起動時のピッチ・ロールを水平として打ち消さない。基準カメラC0にはこの重力整合済み姿勢を使い、既存の絶対姿勢追従・平滑化を維持する。
- 通常モードの内円は `tan(望遠鏡FOV/2) / tan(通常FOV/2)` の比で縮小する。望遠鏡倍率は `gameConfig.panorama.telescopeZoom` で調整する。
- ダウジング関数自身が登録済みIDを除外する。登録リングとチェックマークは望遠鏡モードの星のGL描画内だけで描き、星本体の発光サイズと色を維持する。山の遮蔽も共有する。タップ波紋だけは円形視野内の一時的なUIアニメーションとする。
- 中央下部ボタンと2本指ピンチは同じ `setMode` 遷移を使う。望遠鏡に入るときはカメラ姿勢を維持する。戻るときは端末姿勢があれば通常モードのスワイプ補正と最新姿勢から向きを復元し、センサーがなければ望遠鏡の姿勢を維持する。望遠鏡中のスワイプは通常モードの補正値を変更しない。ピンチ閾値・最低移動量は `gameConfig` で調整する。ズーム演出と円/照準のフェードは画面側で再生する。
- 密度の色は `DensityIndicator` の表示設定を探索円の外縁と共有する。密度アイコンは探索円上端の外側に置く。望遠鏡レーダーは反応文字を視野上側、方向矢印を円周の外側に配置する。中央下部の丸ボタンは発見時に登録操作へ切り替える。位置は視野径とSafe Areaから決める。
- `NormalDensityOverlay` は画面端から透明になるSVGグラデーションと探索円保護マスクを持つ独立UIレイヤー。色は即時更新し、単一のAnimated不透明度を現在値から短く変更する。`pointerEvents="none"` とし、設定は `gameConfig.densityEffect` にまとめる。
- `HorizonCompass` はゲーム内方位の世界ベクトルを共通カメラで投影する。現山画像のアルファ境界を8方位で測った仰角と、その上に浮かせる角度・色・透過度は設定化する。山素材や素材回転を変更した場合は稜線仰角の設定も更新する。背景画像には焼き込まない。
- `ConstellationButton` は左右共通描画とし、左は図鑑、右は制作入口。Safe Areaはアイコンへ適用する。`ownership.creationChoices` と `useCraftingAvailability` が新規・編集可否と拡大状態を管理する。
- Expo RouterのStackで探索→制作へ遷移する。Providerは入口のカメラ姿勢・月・対象IDと確定データを保持する。作業は `ConstellationDraft` のローカル履歴のみで管理し、隠れた探索画面のカメラ更新は休止する。
- 制作画面の背景は `SkyPanoramaView`、線は `ConstellationLines`、操作は `useConstellationGestures`、接続・Undo・当たり判定はReact非依存の `constellation/domain/editor.ts` が担当する。制作の連続ズームは任意の `CameraState.zoom` を共通FOV計算へ適用する。
- 登録星と完成作品を `skyRepository` 経由でAsyncStorageへ保存する。作業データは書き込まない。明示保存は所属・接続を再検証し、直列保存に成功してから確定データを更新する。失敗時は元作品と作業を保持する。命名の「決定」は作業名のみ、「完成・保存」が永続化を行う。

- 各月の星空を `skyId` / `periodKey` で区別する。
- 星座は星のID群・線の順序・顔スタンプの設定を構造化データで保持する。
- ローカル保存から開始し、将来のRepository実装を差し替え可能にする。
- 月替わりは旧データを削除する操作ではなく、アクティブな空の切り替えとして実装する。

## 手描きと完成作品

- `artwork.ts` は星空に固定された接平面とクォータニオン基準姿勢を持つ。`(x,y,-1)` を世界方向へ変換し、既存の透視投影を共有する。ストローク・顔は接平面座標で保存し、画面サイズ・ズームから独立させる。1作品は基準の前方半球内に限定し、背後をまたぐ接続は拒否する。
- `drawingRegion.ts` は丸端帯と平面グラフの閉領域を生成する。面探索前に末端分岐を除き、自己交差成分の内部は保守的に無効とする。和集合・スタンプ包含の差集合には `polygon-clipping` を使用する。
- ストロークは領域境界との交点で分割し、中点判定で内部区間のみ保持する。表示時も同じ領域のSVG ClipPathを適用し、線幅のはみ出しを防止する。接続変更・読み込み・完成時にもクリップする。
- `ArtworkLayer` はガイド/確定線/仮線/画像スタンプを描画する。顔画像は透過を保ち、接平面の四隅を共通カメラで投影した結果に通常のReact Native Imageを重ねる。これによりiOSで小さなSVG画像片が消えるリスクを避ける。`useArtworkGestures` はペン・消しゴム・手のひら・顔の入力を担当し、既存の接続ドラッグとは同じ画面のツール選択で切り替える。
- `brush.ts` は画面上の入力距離と時刻から平滑化した座標を求める純粋関数。`useStampTray` は素材パレットからキャンバスへのドラッグ、仮表示、配置確定・取消を担当する。`fitStampAt` が配置点で収まるサイズを探索し、配置後の移動・拡縮は既存ジェスチャーが担当する。
- 図鑑の削除は `DeleteConstellationDialog` で確認し、Providerの `deleteConstellation` がID指定で作品を除く。その作品を編集中の場合のみ対応する下書きも消す。登録星・他作品は変更せず、既存の直列保存経路を使う。
- `draftHistoryReducer` は接続・絵・顔を一括スナップショットでUndo/Redoする。プレビューとカメラ変更は履歴・保存に含めない。書き込みは従来どおりRepository経由で直列化する。
- `ConstellationsInSky` は完成作品を共通カメラで投影する。望遠鏡時は円でクリップする。`library.tsx` は完成作品一覧と読み取り専用の再観測画面を持つ。
- `ConstellationSelection` で対象を選び、選択後は1セッション1作品に固定する。対象IDはメモリのみ。`replaceFinished` が明示保存された作品を置き換える。他作品は同一投影で25%表示し、操作対象に含めない。当月作品は図鑑一覧からも編集できる。
- `touchTransform.ts` は2点の中心・距離・角度から視点または顔を変換する。開始位置で対象を固定し、描画から2本指への切替は未確定線を破棄する。`brushTexture.ts` はIDから決定的な濃淡と輪郭を生成し、描画レイヤーは同じ座標を投影する。
- 顔はID付き配列で保持し、選択IDは編集画面だけに置く。入力フックは空き位置のタップと素材ドラッグで追加、既存画像のタッチで選択する。プレビューは対象IDだけを置き換えて描画する。星座名は作品の接平面上の下端から投影し、背景とは別レイヤーに置く。
- 月判定は `periodKey(date)` に分離し、現段階では端末のローカル暦を採用する。Providerが定期的に月を確認し、現在月だけ空へ表示する。星配置の月替わり生成・図鑑作品の再編集・クラウド同期は範囲外。

## 開発・品質ルール

- まず探索プロトタイプを実機で評価し、それから星座制作・図鑑へ進む。
- 設定値を集中管理し、UIからの調整を容易にする。
- 型チェックと、位置・モード切替・ダウジング・月判定の単体テストを優先する。
- iOS/Androidでのセンサー・振動差を考慮し、必須操作はスワイプで成立させる。
- Supabase導入時はRLSと認証済みユーザー範囲のアクセス制御を設計する。秘密鍵はアプリに組み込まない。
